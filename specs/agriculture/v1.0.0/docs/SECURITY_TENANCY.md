# WeaveSense-DigitalTwin 身份权限与租户隔离规范

版本：v1.0.0；日期：2026-10-29；时区：Asia/Shanghai。

本规范约束 Web、移动外业、Agent、CLI、MCP、农业 GIS、遥感 Worker、Loom、对象下载及运营后台。目标是在保留现有平台能力的同时，为每个农业资源和异步操作建立可复核的身份与权限边界。规范中的“必须”是开发与发布要求，不表示当前仓库已经达到。

相关文件：[PRD](../PRD.md)、[架构](ARCHITECTURE.md)、[数据与接口契约](DATA_API_CONTRACTS.md)、[验收矩阵](ACCEPTANCE_MATRIX.md)、[来源审计](SOURCE_AUDIT.md)。实际字段、状态枚举和接口路径以数据与接口契约为唯一约定，本文件定义它们的安全语义。

## 1 已知基线与改造目标

### 1.1 AgriScope 的项目角色不是可信登录凭证

固定基线 `571a2dcd9abf8b8a22b66c750ee710b61d482051` 中，前端的 [userStore.ts](https://github.com/autool/AgriScope/blob/571a2dcd9abf8b8a22b66c750ee710b61d482051/frontend/src/store/userStore.ts) 保存并切换用户编码；[growth_monitoring.py](https://github.com/autool/AgriScope/blob/571a2dcd9abf8b8a22b66c750ee710b61d482051/backend/app/api/v1/endpoints/growth_monitoring.py) 接收操作人编码；[project_user_service.py](https://github.com/autool/AgriScope/blob/571a2dcd9abf8b8a22b66c750ee710b61d482051/backend/app/services/project_user_service.py) 按传入编码查项目角色与能力。这些实现可以提供业务流程参考，但集成后的身份必须来自 WeaveSense 的可信会话与服务授权。

农业正式接口不得通过 `operator_code`、`requester_code`、页面下拉、localStorage、任意 HTTP 头或模型生成的 JSON 确定调用者身份。兼容旧接口时，这些字段只能被忽略并由服务器填充，或与可信主体比对后拒绝不一致请求；不能继续作为授权依据。历史审计中的旧编码保留映射及来源，不将未知人员伪装成已验证登录用户。

### 1.2 WeaveSense 的 RLS 已实现，但空范围目前有系统语义

固定基线 `206c82af7ae007f45da4c582f373fbabf027f1b8` 的 [flow_rls.go](https://github.com/newyngwieslash-ops/WeaveSense-Flow/blob/206c82af7ae007f45da4c582f373fbabf027f1b8/backend/internal/database/flow_rls.go) 将未设置或为空的 `app.tenant_ids` 视为系统上下文。生产路由也确实挂载租户中间件，见 [服务入口](https://github.com/newyngwieslash-ops/WeaveSense-Flow/blob/206c82af7ae007f45da4c582f373fbabf027f1b8/backend/cmd/server/main.go)。因此本规范要求对系统上下文的使用进行兼容收紧，而不把“已有RLS”或“缺少scope”直接等同于已复现数据泄漏。

**目标：普通应用角色缺少有效租户上下文时拒绝；系统工作由显式、最小权限的独立角色执行。** PostgreSQL 官方说明了RLS、表所有者及 `BYPASSRLS` 的行为，实施时须按实际版本和角色验证：[Row Security Policies](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)。

## 2 主体与信任边界

### 2.1 主体分类

| 主体 | 身份依据 | 可获得的能力 |
| --- | --- | --- |
| 人类用户 | 平台已验证会话及当前有效成员关系 | 当前租户、工作区与明确授权资源的能力 |
| 用户配置的Agent | 所有者、配置版本、运行人身份与平台能力快照 | 配置权限、运行人权限、资源权限和当前政策的交集 |
| 平台内部服务 | 独立服务凭据或受控签名身份 | 限定受众、API与资源范围，不能继承无限管理员能力 |
| 分析Worker | 独立工作进程身份加已领取任务授权 | 该任务输入及暂存输出，不能任意读取其他租户对象 |
| 外部API/MCP/CLI客户端 | 可撤销的服务账号凭据及授权范围 | 通过同一领域API执行被允许的动作 |
| 设备或边缘网关 | 设备级凭据及服务器保存的归属 | 仅接入已允许的站点、指标和操作；S4后启用 |
| 客服或平台运维 | 平台运维角色，必要时叠加客户限时支持授权 | 默认仅系统健康与工单元数据，不默认读取客户内容 |

租户所有权是组织治理关系，不等于自动获得所有农场原始影像下载权。所有者可以按产品治理规则管理授权，但读取内容仍经当前有效范围检查。服务管理员和数据库迁移者也不能在普通产品请求中复用管理权限。

### 2.2 浏览器到平台

平台复用现有会话机制，农业子应用与主应用使用统一身份。必须配置HTTPS、适当的 `HttpOnly`、`Secure` 与 `SameSite` Cookie策略；有状态写接口执行CSRF保护或等价的可信来源/令牌机制。CORS按实际已授权前端精确配置，不接受任意源附带会话。

浏览器可以请求“切换到某个工作区或农场”，但这是资源选择，不是授权声明。平台必须重新检查用户有效成员关系、工作区归属、农场授权以及资源状态，再确定当前租户。禁止把“用户所属所有租户”自动合成一个无限农业查询范围。需要跨农场分析时，由服务器求得明确的已授权农场集合，并记录输入集合的快照。

登录、退出、会话失效、成员撤销及支持授权到期影响所有入口。浏览器不保存主系统密钥，不把长期访问令牌写进普通localStorage；移动离线数据另按第8节处理。

### 2.3 平台到 GIS 与其他服务

下游身份应具备以下语义，具体字段名称按接口契约统一：签发者、受众、服务主体、代表的用户、租户、工作区、允许能力、资源范围、签发及失效时间、唯一票据ID、授权版本、调用关联ID。

必须逐项执行：

1. 校验签名、允许算法、签发者、受众、有效期及明确的时间偏差范围；缺字段失败，不能降级成旧身份模式。
2. GIS服务将票据范围与数据库资源归属再交叉校验，确保 `farm_id`、`parcel_id`、`asset_id`、`job_id` 都在相同租户和授权关系中。
3. 票据中的租户和用户必须由平台构建；禁止把浏览器或LLM提供的同名字段直接透传为可信值。
4. 服务能力与代表用户的能力取交集。内部服务签名只能证明来源，不能自动证明其对所有农场有权。
5. 服务票据短期有效并支持密钥轮换。长期后台任务使用任务授权及续期机制，不持有用户浏览器会话等待数小时。
6. 票据不能复用于其他受众；写请求另有业务幂等键及载荷摘要。只依靠JWT唯一ID不能替代业务幂等。
7. 密钥只在受控秘密存储和服务运行环境中使用；日志保留密钥标识和校验结论，不保留密钥、完整票据或签名下载URL。

公开入口仅由网关提供。GIS API、数据库、Worker控制端点和内部回调默认处于私有网络，网络隔离作为补充，不代替接口鉴权。

## 3 资源授权与角色

### 3.1 授权判定规则

一次操作必须同时满足：主体已验证、租户有效、成员有效、工作区可访问、资源属于该范围、角色具备动作能力、数据权利允许用途、状态允许操作、相关审批仍有效，以及费用/配额满足要求。

任何一项失败均不能通过前端隐藏、模型自述、管理员参数或旧缓存放行。权限检查必须执行于具体操作边界，不能只在进入页面时执行一次。列表和聚合也需要授权过滤，不能先查全部再由浏览器筛掉无权记录。

对象层级为“租户→工作区/授权关系→农场→地块与种植季→资产/观测/分析/报告”。一个数据集覆盖多个农场时，访问权不能由任一农场自动扩展到整个文件；必须形成获准子集、使用满足整体范围的授权，或拒绝原文件下载。

默认正式外发报告需要作者与审核者分离。单人探索报告可生成并标注为草稿/未经独立审核，但不能自动获得正式发布状态。业务审批作用于具体操作；用户已经授权开发工作，不需要开发Agent在每个工作包之间重复请求许可。

### 3.3 对象权限与错误语义

| 入口 | 必须检查的资源范围 |
| --- | --- |
| 列表、bbox、点选、搜索、聚合 | 在查询前限定农场及租户，游标绑定范围，统计分母同范围 |
| 地块编辑、分割、合并、恢复 | 所有输入地块的归属、写权限、expected_revision、种植季及血缘影响 |
| 影像与分析 | 全部输入资产、AOI与派生用途权限，禁止用合法AOI裁取无权原始影像 |
| 任务详情、日志、进度、SSE | 任务归属与当前访问权，重连游标不能扩大可见事件 |
| 文件下载、Range、缩略图、瓦片 | 内容授权与权利状态；不能因是“小图”或二进制而省略 |
| 报告、导出与分享 | 所有依赖资产的可分发权限、报告版本、共享范围、有效期与撤回状态 |
| Agent与知识检索 | 每一轮主体范围、检索文档ACL、工具能力、动态撤权；引用本身也需可访问 |
| 费用与账单 | 账单所属租户及财务角色，避免普通地块查看者读到供应商密钥或全租户成本 |

认证无效使用明确的认证错误；没有对象访问权时避免泄漏其是否存在。已知可访问对象但缺少动作能力，可以返回权限不足。版本冲突必须保留用户修改并返回结构化冲突；限流、预算不足、来源不可用与数据质量不足不得混用为泛化500。具体HTTP码和错误码以契约固定。

## 4 PostgreSQL 与 RLS

### 4.1 数据库和角色所有权

平台、知识与GIS保持独立数据库或等价明确隔离边界；首版逻辑数据库为 `flow_platform`、`flow_intel`、`flow_geo`。每个数据库只有对应服务写入，跨服务不共享写表凭据。

| 角色类型 | 约束 |
| --- | --- |
| 迁移/owner角色 | 独立凭据，仅部署迁移使用；不进入Web/Agent请求连接池 |
| 普通平台/GIS/知识应用角色 | 无superuser、无BYPASSRLS、非表所有者；只获需要的表和函数权限 |
| 任务Worker角色 | 对任务和输入读取受租户/任务上下文约束；输出只允许该任务命名空间 |
| 系统维护角色 | 单独连接池及显式操作接口；只拥有特定跨租户维护能力，不复用“空scope”作为万能通行证 |
| 报表/支持角色 | 只读必要投影；默认不读取客户原始内容 |

普通应用的租户表策略必须在范围缺失或无效时拒绝，必要表启用 `FORCE ROW LEVEL SECURITY`；同一租户内的农场授权仍需应用级对象检查或专门策略，不能认为 `tenant_id` 相同就足够。

租户上下文在已验证请求的短事务内设置，使用事务局部设置并验证连接池归还后的清理。任何代码路径无法拿到受限事务时应失败，不能自动退回无范围的全局数据库连接。参数化查询、授权后的资源集合和安全数据库角色共同形成边界；RLS不替代它们。

复合唯一约束应带租户范围；资源外键或等价数据库约束必须防止把A租户任务引用到B租户资产。禁止靠应用一次预查后默认永远不发生跨租户关联。JSON载荷中的ID同样应校验，不能只约束主表的tenant_id。

### 4.2 现有空scope系统语义的兼容收紧步骤

1. **盘点**：列出平台/Loom/GIS所有连接池、后台任务、回调、调度器、教育及影视旧路径、迁移、统计、账单、通知和备份工具。标出目前依赖空scope读取全部租户的操作。
2. **分类**：用户业务使用用户授权事务；单租户后台任务使用任务所属租户；真正跨租户调度只读取最小任务索引，再逐租户委托执行；迁移使用独立owner。
3. **准备**：新增角色与受控系统入口，补全tenant_id和关联约束。无法安全归属的历史数据进入隔离待处理，不自动全部归入默认租户。
4. **验证**：在恢复样本上执行新策略、连接池交替请求、用户无租户、退出、角色撤销、Webhook、Agent后台、原教育/影视功能回归。
5. **切换**：协调部署角色凭据和策略，使旧服务实例不再继续使用不兼容空scope路径。采用维护窗口或兼容部署步骤，避免旧新实例混合导致错误结算。
6. **失败处理**：若兼容检查失败，停止农业上线，继续修复；不能为通过演示永久关闭RLS。数据库回退须有可验证备份或兼容迁移，不使用破坏性重置。

验收必须证明：A连接后回池再被B使用不携带A上下文；事务错误/超时/取消后范围不残留；普通连接空scope不能读写租户数据；系统角色无法被普通HTTP参数选择；已存在的合法系统任务仍正常运行。

## 5 异步任务与跨服务执行

### 5.1 授权生命周期

提交分析时固定业务输入版本、可用数据权利、批准动作、价格版本、预算预留及授权范围。领取任务时验证服务主体和当前任务范围；在读取新敏感输入、发布结果、生成下载地址或执行写操作前重新检查必要的动态权限与权利撤回。

成员被撤销后，该用户不能继续看任务日志和结果。后台应停止或取消不再允许的工作，正在进行的纯计算可在安全检查点结束，但不能继续发布给无权用户。真实已产生且有依据的成本仍通过受限账务路径处理，不能为阻止访问而丢失计量；也不能以结算需要为理由向用户重新开放数据。

### 5.2 租约与 fencing

任务领取使用原子条件更新或等价锁机制，产生单调的租约代号/fencing token。心跳只延长当前有效租约；过期后新Worker获得更高代号。每次写进度、发布成果或变更终态都必须验证当前代号和状态。旧Worker即便仍在计算、持有旧临时URL，也不能提交新元数据或触发结算。

计算期间不能持有长数据库事务。事务只用于领取、续约、短状态转换、outbox写入与发布元数据。临时产物路径包括租户、任务、尝试与不可猜测标识；仅凭对象写入成功不能把任务置为成功。

结果先写隔离暂存区，校验大小/hash、格式、输入版本与完整manifest，再在受控事务中发布当前输出引用。失败、取消和旧尝试的孤儿文件按租约及引用检查清理，避免误删另一尝试已发布产物。

### 5.3 取消、重试和未知结果

任务状态按契约统一；取消请求与成功发布竞争时，由一个原子状态转换确定唯一终态。已经成功的任务不能被晚到取消覆盖，已确认取消的任务不能被旧Worker改成成功。任务可成功完成“没有足够数据”的判断，此时业务outcome为 `insufficient_data`，不能展示为有效农学诊断。

非终态任务的自动恢复增加attempt并重新取得租约；终态任务的人工重试必须创建新job，通过 `retry_of_job_id` 关联原任务并重新校验权限、输入版本和预算。禁止把已审计终态改回running以复用旧授权或预算。客户端请求幂等namespace为tenant、可信actor/client、服务端定义operation_kind及API主版本；相同key不同载荷必须拒绝。

跨服务传递使用持久outbox、消费者inbox和业务幂等键；默认接受至少一次投递，通过去重实现一次业务效果。网络或对象存储与数据库之间没有可凭空假设的全局事务，不宣称天然exactly-once。

外部付费调用结果未知时进入对账状态，先查询提供方或使用支持的幂等键恢复。无法判断先前是否执行的外部控制动作不得自动重试。未开始取消释放全部预留；已开始取消按提交前公开的规则结算已确认消耗并释放余额，未知成本保持对账，不臆造金额。

## 6 对象存储、瓦片、缓存与撤回

### 6.1 对象命名和权限

对象桶默认私有。路径应包含受服务器控制的租户/业务类别/资源版本或任务尝试；用户文件名只作为显示元数据，不直接形成路径。路径前缀不是独立授权措施，每次获取对象引用还要检查其数据库归属及用途。

原始影像、外业照片、缩略图、报告、COG Range和MVT都属于受保护内容。GIS与平台使用最小权限存储凭据；前端不获得可列举全桶的凭据。浏览器获准直传时，只能上传指定对象、大小与期限范围，完成后由服务器校验并登记，上传URL不能变成读取其他对象的通道。

### 6.2 两种下载路径的撤回语义

| 路径 | 用途 | 撤回保证 |
| --- | --- | --- |
| 受控代理或可撤销网关token | 默认私有数据；敏感客户资料；需要强撤回的报告/瓦片/COG | 每个新请求重新授权；撤回后拒绝新的读取；已经完成下载的副本无法由服务器远程收回 |
| 短期存储直签URL | 明确允许有限残余窗口的普通大文件或分块请求 | 默认TTL不超过60秒；停止签发后仍可能在到期前访问，必须向用户说明；不能宣称即时失效 |

AWS官方说明预签名URL可在有效期内重复使用，其有效性还受签名凭据影响：[Using presigned URLs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)。具体对象存储兼容实现必须实测，不能只因“S3兼容”假定所有失效行为一致。

敏感资源不采用无法满足撤回要求的直签路径。对正在传输的代理响应应定义连接终止策略；已发出的网络字节无法撤回，产品说明不得承诺抹除客户已经下载的文件。共享token仅授权单份明确版本/范围，保存摘要而非完整可复用秘密，并支持到期和主动撤销。

### 6.3 缓存与前端

私有缓存键至少体现租户、工作区/农场授权范围摘要、资源版本、图层/时间/样式、算法或质量版本、权限/撤回版本。不能使用只有 `z/x/y`、AOI或文件名的全局键。不同用户即使选中同一地理位置，也不能未经授权共享可识别客户信息的响应。

允许在服务端按数据权利共享公共源的物理缓存，但每个租户的授权元数据、派生结果和缓存返回路径仍独立；公共源去重不能泄露另一客户的存在或分析范围。

个人私有结果不进入公用CDN和Service Worker无鉴权缓存。撤回时更新权限版本、清理受影响缓存、停止新签名和共享。对浏览器旧页面，服务端拒绝后续请求并通知界面失效，不依赖前端收到通知才生效。SSE重连、HTTP Range、HEAD、缩略图和错误响应都在相同授权覆盖范围内。

条件请求返回304前必须重新鉴权。强ETag应区分实际字段投影和授权版本，或由当前授权下的实际表示计算；角色降级或敏感字段范围变化不能继续使用旧完整表示的ETag。业务revision不变不代表当前用户可见表示未变。

## 7 上传、遥感解析及外部数据

上传流程依次执行：获得受限会话、分片接收、完整性校验、实际格式识别、受限解析、CRS/几何/波段/权利预检、正式资产登记。正式登记前不可用于分析或对外下载。

必须设置可配置但有上限的文件大小、解压后字节数、文件数、压缩倍率、像元数、波段数、几何坐标数量、解析时间、内存和CPU限额。拒绝路径穿越、符号链接逃逸、重复文件覆盖、格式伪装、解压炸弹和危险外部引用。失败时隔离或清理临时资源，保留脱敏原因码。

GDAL/Rasterio及文档/图片解析在独立、非root、资源受限进程或容器中执行。限制可用驱动及文件访问范围，禁止未经允许的VRT引用、本地路径读取或远程数据路径。不能把用户输入拼接成shell命令。解析服务不持有平台主密钥或所有租户存储凭据。

外部STAC和数据适配器由服务器允许的provider、collection、item等ID解析URL。防SSRF要覆盖解析后的IP、重定向每一跳、DNS重新解析、IPv4/IPv6、回环/内网/链路本地/云元数据地址、URL内凭据、端口和协议。业务确需私网来源时，使用管理员配置的精确目标和专用服务身份，不能通过用户任意URL开放内网探测。

遥感质量控制同时承担错误结果防护：没有源CRS时拒绝猜测；保留scale/offset/nodata；SCL/QA位图按分类处理；输入影像是否可比较由版本化策略判断。未知传感器或处理级别不得通过“字段名称相似”自动当作标准反射率。完整遥感用例见AG-AC-013、018、019、034、035、038。

正式资产登记必须包含来源、权利主体、用途/导出/派生许可、署名、期限、敏感等级和operational/demo标记。软件Apache/MIT许可证不替代影像、底图、模型或客户资料授权。公开演示快照不能作为客户法定边界或真实经营事实的证明。

## 8 移动外业与本地缓存

定位、拍摄和录音使用终端明确授权；保存观测时间、上传时间、定位来源与精度。没有GPS权限或精度不满足门槛时，提供明确手动/待复核路径，不生成虚假精确坐标。EXIF中的个人信息和位置按必要用途保留，发布及导出时执行对应脱敏政策。

弱网草稿按用户、租户、工作区、任务范围隔离。共享设备切换账号时清理或锁定本地敏感内容；退出前提示尚未同步内容，并按照用户选择和产品保留策略处理。短期离线授权不能无限延长服务器权限，恢复联网后重新验证身份、任务状态与数据权利。

重复提交使用稳定幂等键及规范化载荷hash；同键不同载荷返回冲突，不覆盖旧证据。文字记录成功但照片失败时保持待补传状态；不得显示整体已完成。媒体补传也必须验证该记录归属，不能仅凭record_id接收文件。

## 9 Agent、Skill、MCP与开放客户端

### 9.1 数据和指令分离

外部网页、STAC文本、客户文档、图片OCR、模型输出和工具结果都视为数据，不能改变系统权限、服务端工具白名单或运行政策。检索文本中要求泄露秘密、执行shell、访问内网或更换tenant_id的内容不得执行。

Agent获得最小必要上下文：已授权资源摘要、稳定ID、版本、时间、单位、质量与可访问证据引用。禁止把存储密钥、服务票据、客户全库、所有农场原始影像或其他租户资料塞进提示词。对外模型调用遵循租户数据使用策略，只有允许的内容才离开服务边界。

### 9.2 工具执行

工具使用固定、版本化Schema和类型验证；服务器重新解析资源与权限。查询工具不允许任意SQL、文件路径或出网URL；长计算返回任务引用，不让LLM进程直接持有长事务。结果返回资源引用、版本和质量摘要，地图通过受控接口加载详细图层。

每次工具调用记录run_id、call_id、主体、scope摘要、输入hash、版本、审批和预算引用及结果。调用幂等不等于LLM输出幂等，重复请求的业务效果由执行服务控制。模型更换、工具Schema变化和权限变化必须反映到能力快照与兼容检查。

### 9.3 自定义Agent与技能

首版允许租户配置名称、提示词、工作流程、知识范围和已批准工具子集。能力由创建/安装授权、运行人实时权限、资源授权与当前政策共同限制。提示词中的“管理员”“已批准”等描述不具有权限意义。

技能版本及hash固定到运行；升级不改变正在进行的任务。回滚技能也不能恢复已经撤回的工具或数据权限。首版不向租户开放任意脚本在平台或GIS主进程执行。后续若引入可执行技能，须使用无宿主秘密、资源受限、文件系统隔离、受控出网和审计的独立执行环境，并增加对应验收后开放。

外部MCP按连接和工具分别授权，限制目标地址、凭据引用、输出大小、超时、预算及Schema变化；未经批准的工具不因出现在远程列表中自动可用。CLI和SDK调用同一API及计费流程，不直接访问数据库，不内置共享超级token。

### 9.4 操作预览与审批

修改地块、指派任务、发布共享等操作按产品策略产生预览。批准至少绑定动作、资源集合与版本、参数hash、费用上限、执行主体及有效期。执行时重新检查权限和输入版本；任何实质变化使旧批准无效。

业务审批与开发权限属于不同层次：本项目规格已获授权的编码、测试、可逆本地修复可以连续执行，不需要开发Agent每包重复询问；产品运行中的高风险业务动作仍遵守其操作审批策略。真实付款、公网部署、向他人发送消息、破坏性数据操作和物理控制只在用户明确授权的范围内执行。

## 10 计费、商业权益与运营后台

预算、账本和权益由Go平台权威管理；GIS只上报可核验的使用事件，不保存第二个可自由消费余额。费用采用整数单位及固定价格版本，参数范围和估价在执行前可见，不能由LLM或浏览器提交一个任意金额作为可信收费依据。

支付provider回调必须验签、核对商户、订单、金额、币种和状态版本，重复/乱序均幂等。未知支付结果需提供方查询或对账确认；前端跳转成功页面不能直接授予权益。退款使用可追溯补偿分录，不改历史流水。

用户明确选择 `manual_invoice` 的B2B模式时，必须有真实到账凭证、可去重交易标识、订单对应关系和独立复核后入账；上传截图本身不构成到账验证。此路径可以满足所选人工收费渠道的验收，但不代表自动在线支付已接通。未完成真实验收的自助支付入口必须关闭。

平台运营、客服与财务职责分离。客服默认查看故障状态和工单元数据，读取客户内容必须有明确工单、客户授权、最小资源范围与到期时间。支持访问结束后立即停止新请求。运营人员不能通过后台任意修改账本余额、重置审核状态或伪造设备回执。

## 11 审计、备份与数据生命周期

审计包含经过验证的主体及代理关系、租户、动作、资源版本、请求/任务/运行关联、审批与费用引用、结果和时间。普通应用不能更新或删除历史事件；纠正采用追加事件，必要时通过外部检查点或保留存储增加完整性证明。

“不可变审计”首先指应用权限与业务模型中的不可原位修改，不能据此声称拥有数据库最高权限的人在物理上绝不可能修改数据。若合同要求更强证明，应配置独立保留、完整性检查和权限分离并实测。

日志不保存口令、密钥、完整会话、签名下载URL和不必要的客户内容。trace关联采用稳定ID，敏感元数据在授权查询中展开；指标避免无界高基数标签。审计访问本身同样记录并受权限限制。

备份覆盖平台库、知识库、GIS库、对象manifest、配置版本和必要密钥恢复安排；密钥不能仅存在会被一并丢失的单机磁盘。备份加密、访问受限，并在隔离环境执行实际恢复，检验引用、hash、报告、任务状态和账务一致性。

租户注销或数据撤回应停止新处理、撤销共享、更新检索与缓存、终止相关任务并按保留政策清理对象。仍需保留的最小账务/审计记录说明依据与期限；备份中的删除滞后窗口也要说明。清理先检查引用、保留锁和任务租约，不能删除其他租户共享公共源的合法引用。

## 12 部署与依赖供应链

生产使用独立环境及凭据，禁止默认数据库口令、调试接口、公开Worker端口、内置演示管理员和样例密钥。容器非root运行；服务按最小文件与网络权限启动。镜像、依赖、数据库扩展及模型版本锁定，生成实际发布产物的SBOM与许可清单。

当前WeaveSense的 [第三方说明](https://github.com/newyngwieslash-ops/WeaveSense-Flow/blob/206c82af7ae007f45da4c582f373fbabf027f1b8/THIRD_PARTY_UPSTREAMS.md) 已提示tldraw生产许可边界；其 [官方许可说明](https://tldraw.dev/community/license) 区分开发与生产许可。农业构建应移除未使用的tldraw执行引用及未许可使用路径；若启用，应具备适用许可，不修改或绕过许可校验。只隐藏菜单不足以证明发布产物不存在相关使用。

上游导入保留原许可证、NOTICE和修改说明；沿用现有项目时不覆盖既有AGENTS及其他业务。来源代码、演示数据、运行模型、底图服务分别核查，不能把根仓库MIT/Apache当作整套运行系统的统一授权。

## 13 物联网与物理控制边界

S4设备接入使用独立设备凭据与服务器登记归属；设备不能通过自报tenant_id改变客户。序号/事件ID去重，观测时间与接收时间分离，质量、时钟漂移和离线状态明确。设备遥测接入不自动获得控制权限。

S5设备控制默认关闭，只有在具体场景、设备、参数范围、人员授权和现场安全验收齐备后启用。控制命令必须经受控适配器，包含唯一命令ID、有效期、允许范围、幂等/对账规则和执行回执；设备侧具备最大值限制、联锁、急停、手动接管与失联策略。

LLM只能提出可审查的建议或控制草稿，不能直接拼接任意执行器指令。未知执行结果先查询或人工核对，不盲目重放。未获得现场授权或缺少真实设备时可完成模拟测试，但状态保持blocked_external，不能宣称真实控制已验收。
