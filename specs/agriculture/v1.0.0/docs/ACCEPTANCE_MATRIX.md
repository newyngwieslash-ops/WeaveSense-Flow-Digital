# WeaveSense-DigitalTwin 验收矩阵

版本：v1.0.0；日期：2026-10-29；时区：Asia/Shanghai。

本矩阵规定产品开发的通过条件，并将每个功能需求连接到可观察的测试及证据。所有项目的初始执行状态都是 **not_run**；这些条目是待执行的验收规格，不代表已有代码通过。需求正文见 [PRD](../PRD.md)，任务映射见 [开发任务清单](../DEVELOPMENT_CHECKLIST.md) 与 [tasks.json](../tasks.json)，安全规则见 [安全与租户隔离](SECURITY_TENANCY.md)。

## 1 验收层级与记录规则

| 层级 | 必须使用的环境与证据 | 能证明的范围 |
| --- | --- | --- |
| L1 | 确定性单元测试、合成数据、fixture、契约测试 | 算法与局部逻辑，不证明真实第三方服务或农场效果 |
| L2 | 实际PostgreSQL/PostGIS、对象存储、进程、浏览器与Worker，隔离测试租户 | 真实系统集成和错误路径，允许对不属于该用例目标的外部服务使用明确mock |
| L3 | 获准真实数据源/真实第三方接口/真实手机或传感器/客户业务材料 | 相应外部路径与真实使用行为；支付沙箱和生产实付必须分别标记 |

“L2+L3”必须分别留下两类证据。仅有L3截图不能替代权限负例或故障注入，L1 fixture不能替代L3。真实服务不可访问时把对应验收标记为blocked_external并列出缺少的凭证、资料或授权；继续完成无依赖的工作。被阻塞的首版必需条目不能以风险接受、改文案或降低测试层级冒充通过。

执行记录状态仅可为：not_run、running、passed、failed、blocked_external、not_applicable。not_applicable只适用于明确未启用的可选功能，必须记录依据和相关profile，并验证默认关闭；不得用它跳过S0–S3首版必需需求。disabled的设备控制不是“设备控制已验收”。

每条实际执行结果记录：用例ID、任务ID、需求ID、运行时间/时区、代码commit、构建digest、迁移版本、配置hash、环境规格、数据集版本/hash及授权、执行命令/步骤、预期与实际、证据路径、缺陷ID、操作者/复核者、最终状态。凭证及个人信息脱敏，不在证据中保存可复用token。

AG-FR-005/AG-AC-005是持续生效的隔离要求：G0验证隔离框架、基线接口、基础设施和S0已集成的调用链，不要求尚未开发的S1–S3业务功能提前完成。地图、瓦片、SSE、导出、知识检索等在其交付阶段加入相应负例并回归既有入口；G3必须对首版全部实际启用路径执行总验收。阶段结果须记录测试范围和代码版本，S0通过记录不能自动沿用为后续新增路径已通过。

最高优先级阻断缺陷包括：跨租户或未授权资源访问、错误主体记账/扣费、不可恢复数据破坏、历史证据可被静默改写、输入不合格仍伪造可靠分析、未经授权的物理动作。对这些失败不能用整体平均通过率稀释。其余缺陷按影响和修复期限登记；任何降低范围的变更应更新PRD、任务和声明后重验，而非只改状态。

## 3 数据正确性与性能测量协议

### 3.1 必备验证数据

1. 两个空间范围重叠但租户不同的农场；第三个同租户未授权农场；角色范围混合用户。
2. 合成已知几何、不同CRS与单位、经纬倒置、自相交、边界分裂合并、并发修改样本。
3. 可手算红/NIR栅格，含scale/offset、nodata、红+NIR为0、不同像元网格、部分覆盖、云/云影/SCL/QA、跨传感器和物候不匹配样本。
4. 至少一组获准真实影像与实际地块，至少一次真实外业/手机验证。样例OSM地块不得作为客户法定边界或经营权证明。
5. 有来源和适用范围的农业知识；含提示注入和过时结论的对照材料；真实模型未接入时保留明确未接入状态。
6. 成功/失败/取消/未知消费四组计费链，重复与乱序事件、Worker失联及过期租约样本。

合成集NDVI误差阈值1e-5和面积相对差0.5%仅衡量实现与参考算法的一致性，不代表卫星观测或地块边界具有该精度。真实农学有效性按作物/地区/季节与地面观测另行验证。质量阈值、最小有效面积和可比时间差必须有明确版本，测试记录实际配置。

### 3.2 试点性能目标

下表为待实测的工程验收目标，不是现有仓库的性能结果或对客户的SLA承诺。

| 项目 | 基准输入与方法 | 目标 |
| --- | --- | --- |
| 环境 | 暂按8 vCPU、32GB RAM、SSD；记录数据库、Worker、浏览器、网络和对象存储部署位置；资源不足时按比例重新定义并批准测试档 | 结果只适用于记录的环境 |
| 查询数据 | 每租户10万地块，至少2租户；空间分布含密集区域和复杂边界；按窗口/分页或MVT读取 | 禁止全量GeoJSON进入浏览器 |
| API查询 | 20个并发会话、每会话3秒思考时间、混合地图/详情/任务/报告请求；预热5分钟，测30分钟，重复3轮 | 常见Geo API p95<2秒，5xx/非预期错误率<0.5%；同时报告p50/p99和每类请求结果 |
| 地图交互 | 约5000要素以内窗口或等价瓦片，固定中档桌面浏览器与记录的网络，冷热缓存分开 | 常见切换/定位交互p95<3秒；移动端单列结果，不套用桌面阈值 |
| 提交分析 | 不等待计算或外部下载，仅完成持久化、预算和受控排队 | p95<1秒；任务不丢失 |
| 栅格任务 | 至少一个5000万像元、多波段输入，使用分块与概览；明确配置Worker内存上限，例如8GiB | 不超限OOM，不把全幅中间数组任意复制；总耗时/峰值RSS/字节传输量/成本如实报告，不能由小图外推省域性能 |
| 公平性 | A租户持续投递重任务，B租户按配额低频使用 | B可在配置的排队公平策略下持续获得执行机会，无无限饥饿 |
| 稳定性 | 发布候选至少24小时代表性试运行，含预定故障、外部超时、取消和恢复 | 无未解释的任务丢失、重复结算、越权、持续增长的孤儿文件或资源泄漏 |
| 恢复 | 在独立环境恢复完整数据库/对象/密钥引用并抽样验证 | 试点RPO<=24小时、RTO<=4小时；未验证不宣称达到 |

查询准确性不因性能测试而关闭授权或减少质量校验。遥感总耗时取决于算法、影像和网络，应先建立基准再为各规格制定资源与时限，不能给所有影像承诺统一秒级结果。容量、成本与阈值变更必须保留新旧基准。

## 4 逐项验收

每条AG-AC-nnn精确对应同号AG-FR-nnn；相关NFR列在条目内。以下证据要求是将来开发时必须提交的材料，当前均未执行。

### AG-AC-001 组织、成员与邀请

- **需求与阶段**：AG-FR-001；S0；AG-NFR-001, AG-NFR-018。
- **最低证据层级**：L2。**执行状态：not_run**。
- **前置条件**：租户A、B和有不同角色的用户，邀请有效期已配置。
- **操作**：创建邀请、接受、重复接受、过期接受并撤销成员。
- **通过条件**：邀请单次有效，组织与成员关系一致，撤销后新请求失去原范围。
- **必须验证的反例**：跨租户接受、篡改角色、重复邀请回调不能扩大成员权限。
- **交付证据**：邀请事件、成员行、撤销前后HTTP记录和审计关联ID。

### AG-AC-002 统一登录与会话

- **需求与阶段**：AG-FR-002；S0；AG-NFR-001, AG-NFR-012。
- **最低证据层级**：L2。**执行状态：not_run**。
- **前置条件**：同域主工作台和/agri子应用，真实登录服务。
- **操作**：登录后访问两应用、登出、会话过期和口令重置后再访问。
- **通过条件**：共用可信主体，退出后后续受保护请求拒绝，前端不保存可冒充用户的operator_code。
- **必须验证的反例**：伪造cookie、localStorage身份和客户端user_id不能登录；开放重定向被阻断。
- **交付证据**：浏览器操作记录、请求响应、会话生命周期日志。

### AG-AC-003 工作区与农场授权

- **需求与阶段**：AG-FR-003；S0；AG-NFR-001, AG-NFR-004。
- **最低证据层级**：L2。**执行状态：not_run**。
- **前置条件**：A用户只授权农场A1，A2未授权，B租户有B1。
- **操作**：分别查询地块、影像和任务，并尝试切换workspace与farm_id。
- **通过条件**：服务器从实际成员关系解析范围；同租户未授权农场和其他租户资源均拒绝。
- **必须验证的反例**：合法token搭配另一农场ID、租户ID、workspaceID不能形成混合权限。
- **交付证据**：角色绑定快照、允许/拒绝请求对照及无敏感内容的响应摘要。

### AG-AC-004 角色及能力策略

- **需求与阶段**：AG-FR-004；S0；AG-NFR-001, AG-NFR-008。
- **最低证据层级**：L2。**执行状态：not_run**。
- **前置条件**：至少viewer、analyst、editor、field_operator、reviewer、farm_manager、tenant_admin、billing_admin样例。
- **操作**：按安全文档逐格执行关键读写，并在会话中途降低角色。
- **通过条件**：角色能力与资源范围同时满足才放行；角色变更影响后续调用。
- **必须验证的反例**：仅拥有billing_admin不能读取农场影像；reviewer不能审批自己提交的正式发布。
- **交付证据**：权限矩阵执行记录、角色变化事件和拒绝理由码。

### AG-AC-005 租户全链路隔离

- **需求与阶段**：AG-FR-005；S0；AG-NFR-001, AG-NFR-016。
- **最低证据层级**：L2。**执行状态：not_run**。
- **前置条件**：A、B两租户地理范围重叠，建立S0基线接口及基础设施清单；随功能交付增加同名资产、报告和知识文档。
- **操作**：G0先对已存在和本阶段集成入口交叉访问；S1–S3逐步增加列表、详情、bbox、瓦片、SSE、任务、下载、检索负例，G3覆盖首版全部启用路径。
- **通过条件**：当前交付范围内任何入口只返回授权范围；缺租户scope的普通数据库事务拒绝；A结果不进入B缓存；新增入口未补负例不能沿用此前阶段通过状态。
- **必须验证的反例**：更改路径ID、参数tenant_id、SSE游标、MVT坐标或缓存命中顺序不能泄露。
- **交付证据**：按阶段记录的入口覆盖清单、自动化越权套件、数据库策略与角色检查、缓存键与追踪摘要；G3另有全路径总验收记录。

### AG-AC-006 服务身份与代理授权

- **需求与阶段**：AG-FR-006；S0；AG-NFR-001, AG-NFR-010。
- **最低证据层级**：L2。**执行状态：not_run**。
- **前置条件**：平台与GIS签名密钥及独立audience，短期身份票据。
- **操作**：用正确票据调用GIS，再测试过期、错误audience、错误issuer、重放写请求及key轮换。
- **通过条件**：验证服务身份、有效期和授权范围；写请求幂等；轮换可平滑验证有效旧票据。
- **必须验证的反例**：浏览器直连内部GIS、unsigned票据、仅传operator_code和LLM生成tenant_id均失败。
- **交付证据**：票据字段脱敏样本、签名验证测试、轮换记录。

### AG-AC-007 农场档案与区域配置

- **需求与阶段**：AG-FR-007；S1；AG-NFR-003, AG-NFR-014。
- **最低证据层级**：L2。**执行状态：not_run**。

- **操作**：新建农场、修改名称和管理范围、查询跨区域边界。
- **通过条件**：区域不硬编码为黑龙江；保持稳定farm_id；单位和时区配置可追溯。
- **必须验证的反例**：用不相交边界或错误行政区关联时阻断或明确提示，不能静默改坐标。
- **交付证据**：农场API记录、边界校验、配置版本和界面截图。

### AG-AC-008 稳定地块与边界版本

- **需求与阶段**：AG-FR-008；S1；AG-NFR-003, AG-NFR-004。
- **最低证据层级**：L2。**执行状态：not_run**。

- **操作**：修改边界并读取历史、现行与引用结果。
- **通过条件**：parcel_id稳定；新边界生成新revision；旧分析保留输入版且标明历史。
- **必须验证的反例**：覆盖旧geometry、引用不存在revision、并发相同base_revision写入均不能静默成功。
- **交付证据**：版本行、并发冲突响应、历史查询与分析输入清单。

### AG-AC-009 种植季与作物品种

- **需求与阶段**：AG-FR-009；S1；AG-NFR-003, AG-NFR-014。

### AG-AC-010 地块分割合并血缘

### AG-AC-012 矢量导入导出

- **需求与阶段**：AG-FR-012；S1；AG-NFR-002, AG-NFR-003, AG-NFR-010。
- **最低证据层级**：L2。**执行状态：not_run**。

## 6 证据目录与签收

开发实现可在项目的 `evidence/agriculture/<build-id>/` 生成脱敏证据，索引至少含 `acceptance_id`、`task_ids`、`requirements`、`environment`、`commit`、`dataset_hashes`、`status`、`artifact_paths` 和 `executed_at`。视频、日志和文件名只作定位，真正通过以可复核的输入、输出与状态断言为依据。证据存储位置、访问控制及保留时间应按客户数据政策配置。
