# WeaveSense-DigitalTwin 完整开发方案

版本：1.0.0  
日期：2026-10-29，Asia/Shanghai  
交付目标：将 WeaveSense-Flow 的平台能力与 AgriScope 的空间能力组合为可收费、可审计、可恢复的农业 Agent SaaS。本文规定实施顺序和完成条件；不是已经完成开发或验证的声明。

配套依据：[PRD](PRD.md)、[技术架构](docs/ARCHITECTURE.md)、[数据与 API 契约](docs/DATA_API_CONTRACTS.md)、[144 项开发清单](DEVELOPMENT_CHECKLIST.md)、[机器任务清单](tasks.json)、[验收矩阵](docs/ACCEPTANCE_MATRIX.md)。逐项依赖以 tasks.json 为准；本方案的并行建议不改变其中的任务依赖。

## 1. 实施原则与首版范围

首个商用版本必须完成 S0–S3。S1 可完成真实农业数据工作台，S2 可开展邀请制试点，但都不能自动替代 S3 的收费、隔离、恢复和现场证据门禁。S4 持续监测、S5 预测决策单独排期；没有真实设备、历史数据或农学验证时，相关任务保留 blocked_external，不把演示曲线当成上线能力。

实现选择已冻结为：Go 平台掌握身份、Agent、审批与账本；FastAPI/PostGIS 掌握农业事实；Python Worker 执行遥感；Loom 管理知识证据；Vue 同域农业子应用与 React 主平台并存。服务间通过版本化 API 与 Outbox/Inbox 交互。无需为统一语言或前端框架先重写全部上游。

开发必须逐段交付可运行的业务链：请求、授权、领域数据、后台任务、地图结果、费用、异常、审计全部连通。数据不足、来源撤回、租约失效、预算不足和外部结果未知属于正式产品状态，不能只完成成功路径。

产品范围不包括未经验证的疾病确诊、确定性产量预测、法定灾损认定或自动设备控制。范围内的异常筛查、影响初评、人工复核和报告必须使用准确名称，并保留数据质量和适用条件。

3. 将 AgriScope 提交 571a2dcd9abf8b8a22b66c750ee710b61d482051 受控导入 services/agri-gis；记录来源、导入方法、许可证、NOTICE、原目录与新目录映射。

6. 建立语言与镜像兼容矩阵。版本来自锁文件和实际构建结果，分别固定 Go、Node、Python、GDAL/Rasterio、PostgreSQL/PostGIS、前端包管理器。
7. 建立农业产品 profile，原有产品配置可继续构建。农业生产路径移除未授权 tldraw 功能；底图、字体、影像、模型、容器及运行工具各自登记许可。
8. 更新架构差异、风险、真实命令和工作状态，形成 G0 所需证据。尚未完成身份与 RLS 改造之前，只允许隔离样例，不接入客户正式数据。

本轮对上游的判断来自固定代码快照，未独立跑通构建或压测。[Flow 固定版本](https://github.com/newyngwieslash-ops/WeaveSense-Flow/tree/206c82af7ae007f45da4c582f373fbabf027f1b8)；[AgriScope 固定版本](https://github.com/autool/AgriScope/tree/571a2dcd9abf8b8a22b66c750ee710b61d482051)。W00 的实际运行结果可修正实施细节，不能改变租户隔离、数据真实性和账务守恒要求。

## 5. 推荐实施顺序：四条可演示的完整链

### 5.1 第一条链：真实地块进入地图

完成统一登录后，用两个隔离测试租户创建工作区和农场；导入小型获准矢量，预览 CRS、面积、属性错误和重复编码，确认后提交不可变版本。地图及表格显示同一数据，用户编辑节点触发 expected_revision 检查；另一个用户并发保存必须收到冲突。

交付包括迁移、API、前端、权限负例、来源权利和导入错误报告。随后增加种植季、分割合并、历史恢复、视窗分页/MVT。移动端先具备手工采集与定位证据，正式巡查工单在 S2 完善。

### 5.2 第二条链：影像到可复算结果

接入一个实际可用且商业用途明确的数据源，固定样例 Item 与资产版本。优先使用同传感器、同产品级别的少量影像验证波段、反射率scale/offset、mask、nodata与CRS。记录来源响应和内容hash；不在CI每次无界下载整景。

分析提交在平台获得 quote/operation/reservation，经 Outbox 到 GIS 后成为 job；Worker 分块读取，生成统计与COG，校验 manifest 后发布结果。地图引用 result/layer_id，详情展示有效覆盖、观测日期、像元尺度和算法版本。失败、数据不足、撤回与取消都有独立展示。

先以零价内部计划完成全链计量，随后接入实际价格与成本；这不会豁免 S3 商业计量验收。至少验证一次 Worker 被杀、租约转移、旧Worker迟到发布、事件重复投递、取消与完成竞态。任何一种都不能导致两份权威成果或重复收费。

### 5.3 第三条链：Agent到人工复核的报告

把选中农场、地块、种植季和时间窗作为服务端重解析上下文。Agent先读取已有观测，再按预算提交分析；长作业返回可追踪引用，完成后继续解释证据。异常仅作为候选，用户批准后创建巡查工单。

巡查员提交GPS、照片和结构化结论；审核人确认或驳回。报告组合统计、地图、来源、时相、算法与质量限制，生成结构化JSON和PDF；图件数字与正文来自同一快照。发布需按项目策略审核，默认作者和审核人分离。修改任一来源或报告revision后，原批准不可复用。

这一链覆盖工具权限、提示注入、资料不足拒答、自定义Agent权限交集、审批过期及知识来源撤回。评测不仅查看回答是否流畅，还核对工具是否选对、数值是否一致、证据是否可访问和任务是否实际完成。

### 5.4 第四条链：付费客户与运营恢复

选择并声明实际经营收费方式。在线自助渠道必须完成签名回调、重复和乱序通知、续期、退款及授权小额真实支付；商户凭据不足时保持关闭。用户明确选择合同/对公模式时，记录真实订单与到账凭证，由独立财务人员复核开通权益；它不使自助支付渠道自动通过验收。

接入实际对象存储、域名和密钥管理，完成下载/共享撤回、客服限时授权、数据导出注销、账本对账及全量恢复。CLI、OpenAPI及最小SDK使用相同权限和计量入口，完成无界面条件下的提交、查询、取消和导出验收。最后以真实试点反馈、成本和恢复证据决定可开放范围。

## 6. 各技术层实施要求

| 层 | 必须实现 | 关键工程检查 |
| --- | --- | --- |
| 平台Go | 农业资源适配、能力范围、签名委托、operation投影、报价/账本、工具注册 | 沿用既有运行链扩展点；不复制身份、审批或余额体系 |
| GIS/FastAPI | 领域服务、PostGIS查询、资产与权利、任务状态、审核/报告事实 | 所有入口受可信委托；短事务；请求字段不能提升权限 |
| Worker | 任务领取、心跳、分块计算、资源上限、manifest、fencing发布 | 计算不持有长DB事务；临时路径隔离；失租约不能发布 |
| 数据库 | 三库所有权、RLS、复合租户约束、索引、不可变版本与审计 | 迁移角色和运行角色分离；连接池不泄漏上次租户上下文 |
| 对象与瓦片 | 分片/校验、COG、私有代理、版本缓存、生命周期 | 无公共客户影像；签名URL不是可即时撤销的会话 |
| React/Vue | 同域登录、深链、地图工具、版本冲突、任务/费用/缺数据提示 | 不在浏览器自行推断权限；CSRF与CSP落地；不复制会话 |
| Loom | 数据来源、权利、租户检索、证据版本、撤回传播 | 文档内容不具备提升工具权限的能力 |
| Agent/CLI/MCP | 有类型契约、权限交集、报价、审批、幂等和审计 | 所有入口走同一业务授权，不能产生独立“管理员捷径” |

数据库索引以实际查询计划为依据：地块几何GiST、tenant/farm/状态等过滤组合、任务状态与租约、事件重试时间、去重唯一键均需要覆盖。不能仅因存在索引就宣称达到性能目标；需记录 EXPLAIN 与实际数据分布，但不要把用户敏感数据写进测试日志。

空间算法明确输入范围、单位、缩放、像元对齐、有效像元统计、容差与异常输出；算法版本进入结果manifest。UI中的比例、亩/公顷、色阶与有效样本数由结构化结果计算，不由LLM重新编造。

## 7. Windows 11、WSL2 与本地开发

### 7.1 推荐环境

Windows 11 开发机使用 WSL2 的 Linux 工作区，Docker Desktop 启用 WSL2 backend 和目标发行版集成，容器使用Linux模式。Go/Node/Python与GDAL按仓库锁定版本运行；优先把存在系统依赖的GIS/Worker放在构建好的容器内，以减小Windows原生库差异。真实生产仍部署到受控Linux环境，不把开发机当商业服务器。

根据 [Microsoft WSL 安装指南](https://learn.microsoft.com/en-us/windows/wsl/install)，尚未安装时可在具有相应权限的PowerShell中使用 wsl --install；该操作可能涉及系统设置与重启，应由用户安排。已安装时先查看实际状态。Docker的WSL2配置与要求按 [Docker官方说明](https://docs.docker.com/desktop/features/wsl/) 核对；工具的适用许可也要进入W00软件清单。

以下仅为环境检查命令，并非项目已经存在的一键启动实现：

```powershell
wsl --status
wsl --list --verbose
```

在目标WSL发行版中检查：

```bash
docker version
docker compose version
git --version
```

源码、虚拟环境、node_modules和数据库开发卷优先位于WSL的Linux文件系统；通过编辑器的WSL支持访问。大型影像需要预估临时盘和Docker/WSL磁盘空间，禁止把磁盘耗尽后的失败伪装成数据不足。不要同时配置相互冲突的Docker守护进程；现有安装先识别，再按官方文档调整。

本地无需真实支付也应能确定性验证预算预留、取消、重复回调与对账状态机。真实支付、真实LLM和真实STAC另设live门禁，分别提交证据；一个真实来源成功不能替代另一供应商未完成的验收。

## 8. 三种部署配置

| 项目 | dev | acceptance | production |
| --- | --- | --- | --- |
| 目的 | 个人开发、确定性CI | 与生产权限一致的集成及live验收 | 获准客户的商业服务 |
| 数据 | 显式fixture/demo | 获准样例与指定真实试点，分区隔离 | operational，来源和用途已验证 |
| 数据库 | 可同一容器集群，三库三套角色 | 三库和生产等效RLS/权限 | 托管或受控PG/PostGIS，备份与监测就绪 |
| 对象 | 私有本地兼容服务 | 指定真实对象后端，测试桶 | 私有桶/代理，生命周期与恢复策略 |
| 计费 | 零价计划，完整账本 | 测试价与获准小额实付/合同验证 | 已选收费方式、真实价格版本及对账 |
| 模型 | 显式stub或可选开发凭据 | 至少选定模型真实执行 | 租户/系统受控凭据、成本上限 |
| 网络 | 仅本机入口，内部容器网络 | HTTPS和严格网络边界 | 公网仅入口，服务/DB/Worker私网 |
| 日志 | 可详细但无秘密和个人原文 | 与生产脱敏/保留一致 | 权限化查询、保留和告警 |

小规模试点可以采用受控Linux主机和容器编排，数据库/对象使用可恢复的持久存储。是否采用Kubernetes取决于团队运维能力与已测负载，不作为首发强制依赖。共享主机要明确Worker资源限额和数据库保护，不能默认与Web争抢全部CPU/内存。

配置按“公共非敏感配置、秘密引用、功能开关、租户权益”分别管理。功能开关只能关闭能力或限定范围，不能绕过鉴权。重要配置缺失时fail closed；平台仍可展示清楚的不可用原因，不能静默切换成演示数据。

## 9. 迁移、兼容和回滚

### 9.1 schema与身份迁移

使用 expand → migrate → verify → switch → contract 的方式。先新增兼容字段/表/API，再做小批量回填和核对；新旧应用在一个明确窗口同时兼容。数据量大的操作避免长时间锁表，批量进度和重试可追踪。删除旧字段、旧端点和旧索引必须晚于消费者迁移与回滚窗口。

RLS收紧必须先盘点空scope当系统权限的既有路径，为后台任务和系统服务建立显式身份及最小范围，再执行负例回归。若旧模块未适配，不允许以全局BYPASSRLS、owner运行或允许空租户的方式“临时修好”。发布回滚也不能恢复会泄露租户数据的宽松策略；应暂停相关入口，修复兼容调用。

每库独立迁移版本，由唯一所有者执行。部署前检查migration drift及应用兼容范围，迁移运行角色不用于服务常态连接。应用回滚不自动等于数据库回滚；不可逆迁移必须有受演练备份恢复或向前修复方案。

### 9.2 旧AgriScope数据迁移

先生成dry-run映射清单：旧项目、文件、图层、调查记录、用户名/编码、空间与时间字段。租户/农场归属由明确输入映射，不按operator_code猜测。不确定归属、CRS、数据权利或演示属性的记录进入quarantine。

先复制并计算原件hash，保留原路径来源；再转换新模型并核对数量、面积、时间、字段、文件大小和引用。导入失败保留逐项原因和断点，不删除原始数据。新业务经过人工抽检和授权后切换；旧只读查询可在窗口内保留，不能建立双写的第二权威。

分割合并和历史边界不能被一次迁移压成当前几何。旧分析无法恢复算法/输入版本时标为legacy_unverified，允许查看但不能当作新模型验收证据。迁移产生的source_refs和hash进入后续报告链。

### 9.3 生产变更与回滚操作

发布前冻结版本、镜像digest、Schema、迁移号、配置与开关清单，备份三库和对象manifest，记录恢复点。使用小范围租户验证或受控维护窗口；新任务入口可暂停，已有作业按预定策略排空或安全暂停。

回滚时先阻止新副作用，识别运行中的operation/job、预算、审批、支付回调和Outbox。兼容旧版本的组件可回退镜像；已有新格式副作用必须由对账/兼容处理完成，不能简单删库或清队列。外部支付已发生时不通过恢复旧数据库“抹除”，恢复后仍需与provider状态对账。

回滚完成必须重新验证RLS、下载/瓦片、任务租约、共享撤回和预算守恒。已撤回的资料与令牌不能因为备份恢复重新可访问。记录实际中断时间、恢复点和丢失/补偿范围，再决定恢复服务。

## 10. 验证与证据策略

验收分为确定性数值/单元、契约、真实本地集成、外部live、农场现场、真实商业和真实设备证据。各层用途不同：fixture能证明算法回归与权限路径，不能证明外部数据可获取、农学效果或客户已付款。

每个工作包完成时提交：实际改动路径、契约/迁移版本、执行命令、返回结果、关键日志脱敏摘要、生成成果hash、未通过项及限制。测试必须验证行为，不只是镜像实现断言。失败应修复或明确阻塞，不将assert删去后标完成。

发布前必须完成以下四组高风险验证：

1. **租户与数据权利**：换ID、伪造上下文、连接池复用、跨租户缓存、瓦片/下载/SSE、检索、报告、后台任务和CLI越权；来源撤回与共享到期。
2. **持久性与资金**：重复提交、响应丢失、Worker宕机、失租约、取消/完成竞态、对象发布失败、重复/乱序事件、费用未知、对账冲正和恢复后重放。
3. **空间与农学边界**：CRS/轴序、面积、分割守恒、反射率缩放、QA/mask、nodata、分辨率、物候不匹配、低有效像元与缺数据拒绝。
4. **实际产品使用**：真实影像来源、真实模型工具、地图/报告/外业一致性、Android/iOS实际浏览器、选定收费方式、用户导出注销和备份恢复。

性能采用PRD定义的统一测量协议：8 vCPU/32 GB/SSD参考环境、10万地块目录、20会话、受限地图视窗及5000万像元分块场景。记录冷/热缓存、浏览器/网络、几何复杂度、实际Worker并发、对象服务位置、p95/峰值资源/错误率；未达到即说明瓶颈与降额方案。p95<2秒查询、<1秒提交、地图<3秒均为目标，非已有实测承诺。

S3前执行隔离恢复演练，核对三库与对象引用、RLS、任务和账本；RPO≤24小时、RTO≤4小时只是试点目标，只有演练结果能支持实际SLA。不要为追求更高宣传数字先引入未经运营验证的复杂集群。

## 11. 开发Agent与多人协作方式

任务状态使用 not_started、in_progress、blocked_external、blocked_internal、review、done，具体字段遵循清单。done必须满足依赖、交付和验收，未执行live步骤不能写“基本完成”。开发Agent读取SPEC_ROOT/docs/implementation/STATUS.md后从可执行依赖继续，不在每个工作包结束后反复征求继续许可。

适合并行的任务分给不同worktree和明确路径所有者；数据库迁移号、公开Schema、共享身份与账本模块必须有统一协调者。代码合并前运行相关契约和既有模块回归，不能在共享目录同时重写同一文件。单个Agent可顺序承担这些职责，但不能省略复核。

每轮推进的记录格式固定为：已完成任务及证据、实际风险与差异、阻塞项及所需输入、下一批满足依赖的任务。上下文压缩或交接时以状态文件和提交为恢复依据，不能重新生成一个空项目覆盖当前成果。

默认授权包括本规格范围内的本地开发、测试、修复与隔离分支工作。真实购买、付费测试、公网部署、对外发布、发消息、强推或删除客户原始数据需要对应具体授权；开发Agent先准备可审查的改动、费用/范围、回滚与证据，再对尚未授权的动作申请。已有授权不重复请求。
