## 2 人工交叉审阅

本轮已对身份/租户、异步作业、费用、阶段和数据契约进行交叉审阅，统一了以下关键规则：

- 异步提交先持久化 operation，GIS 接单后再关联 job；job_id 尚未出现不表示远端没有执行。
- 网络超时、回执丢失和外部状态未知先查询/对账，不能直接释放必要预留。
- 终态任务人工重试创建新 operation/job，用 retry_of_job_id 保留来源，并重新授权预算。
- 任务状态、成果质量与有效性独立；数据不足不能伪造为有效农业结论。
- 租约与 fencing 防止旧 Worker 发布；取消/成功竞争唯一终态；费用消息按业务键去重。
- 强 ETag 区分实际授权下的表示；降权后不能复用旧的含敏感字段表示。
- G0 验已有入口与隔离基础；后续功能同步补负例；G3 复验首版全部路径。
- 内部调用可选择类型化 API，S3 对外 MCP 能力仍按需求验收。
- manual_invoice 只在用户明确选择且有真实到账、独立复核时构成其收费路径证据。
- 预签名 URL 有残余有效窗口；在线授权代理和已下载副本的撤回语义不同。
- JSON 与 Markdown 使用同一任务状态枚举，任务范围变更不能替代首版必需验收。

交付压缩包按本目录完整生成，包含四份主文件和全部支持文件。打包过程检查 ZIP CRC、成员文件与本地字节一致性，并核对 MANIFEST.json 内的 SHA-256。manifest 不对自身作哈希。独立主文件和合订本为阅读便利副本，正式开发使用 ZIP 内完整目录。
