# WeaveSense-DigitalTwin 完整开发任务清单

版本：1.0.0 ｜ 日期：2026-10-29 ｜ 状态：历史进度恢复登记；当前统计见末尾生成区。

本文件和 `tasks.json` 来自同一任务数据。共 **18 个工作包、144 项任务、80 项功能需求和 20 项非功能需求映射**。每项任务包括依赖、实现、产物、可观察验收、验证与外部条件。DT-001–012 保留已确认历史完成状态，其余进度见生成区；历史完成不等于运行环境重置后已重新验收。文档结构校验通过不表示软件已完成或已具备商业运行证据。

## 1. 执行规则

将整套规格放到 `SPEC_ROOT = PROJECT_ROOT/specs/agriculture/v1.0.0`。先阅读 PRD、架构、数据/API 契约、验收矩阵及开发 Agent 提示词，再从 W00 开始。保留上游既有规范与工作区修改；不以本规格覆盖仓库根目录的 PRD 或 AGENTS。

- **执行顺序看依赖。** ID 是稳定追踪标识；例如地图任务可依赖之后编号的分析任务。满足依赖的已授权任务可连续推进，不必每个包再次询问。
- **首发范围是 S0–S3。** W00–W15 共 128 项；W16、W17 共 16 项为 S4/S5 后续扩展。S3 的受控 CLI、OpenAPI、SDK/MCP、商业计量与收费路径均属于首个商用版本。
- **阻塞只影响实际受影响范围。** 缺少影像账号、客户数据、付款凭据、设备、真实环境或明确现场授权时，记录 `blocked_external`、所需输入和可继续事项。不得将整个项目停在等凭证，也不得用 mock/fixture 冒充真实验收。
- **每包回填证据。** 在 `SPEC_ROOT/docs/implementation/STATUS.md` 及按包命名的证据记录中更新任务状态、变更文件、命令、环境、提交、结果及剩余风险。只有实现与适用验收都有证据才标完成；部分完成仍保留未完成验收。
- **状态枚举固定。** 只使用 `not_started`、`in_progress`、`blocked_external`、`blocked_internal`、`review`、`done`。`review` 表示待复核而非完成；`done` 必须有适用验收证据。没有 `cancelled` 状态；取消或延期需求须先形成明确范围决策，并同步 PRD、任务和验收，不能自行移除首版必需任务来绕过发布门禁。
- **完成代码不等于获准外部行动。** 用户没有授权的真实扣费、真实控制、公开部署、对外通知、破坏性重置与远程推送，先形成可审查产物；不伪造授权或执行结果。已授权范围持续推进。
- **验收链接有明确含义。** `AG-AC-001..080` 分别对应同号 `AG-FR`；NFR 还必须执行验收矩阵规定的安全、恢复、性能和可维护性门禁。关联不表示单项任务独自满足整个需求。

## 5. 结构校验与机器执行提示

- 144 个任务 ID 连续且唯一；每包 8 项；原始规格初始均为 `not_started`，当前状态由 JSON 同步。
- 80 个 FR、20 个 NFR 均有任务映射；不存在未声明需求编号。
- 所有依赖均存在、无自依赖、无循环；没有任务依赖于更晚阶段的任务。
- 每项任务至少 3 条实现要点、2 条产物、2 条验收、2 条验证；JSON 与 Markdown 使用同一数据源。
- `tasks.json.topological_execution_order` 提供合法排序；并行执行仍须避免共同文件和共享迁移冲突。状态改变后重新计算就绪集合。
- `tasks.json.conditional_dependencies` 记录 S5 物理控制的条件门禁；不启用控制时必须保留明确禁用状态，不能把未做的真实控制验收标通过。
- 本清单的结构校验不代表软件验收；已执行的历史工作和恢复后的验证分开记录，真实数据、真实支付与现场验收不由此推定通过。
