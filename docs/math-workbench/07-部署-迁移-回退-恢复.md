# 07 部署配置、迁移、回退与恢复

## 配置项
| 变量 | 位置 | 说明 |
| --- | --- | --- |
| FLOW_MATH_SERVICE_URL | Go 后端 | 未设置时不注册 /api/edu，也不启动 worker（功能整体关闭） |
| FLOW_MATH_SERVICE_KEY | Go 后端 | ≥32 字节；与 MATH_SERVICE_KEY 相同；通过密钥管理分发 |
| FLOW_MCP_INTERNAL_TARGETS | Go 后端 | 可选。精确内网 MCP 目标 JSON 数组（端点、工具清单、凭据引用），格式错误时启动失败；未设置时网关保持只连公网 https。见 03“Agent 侧数学工具” |
| EDU_ARTIFACT_URL_KEY | Go 后端 | 可选；签名链接密钥，默认从服务密钥派生 |
| EDU_MATH_JOB_BUDGET_MICRO | Go 后端 | 单作业预留上限，默认 120000 |
| MATH_SERVICE_KEY、MATH_DATA_DIR、MATH_LISTEN | 数学服务 | 数据目录需持久卷；监听地址仅限内网 |

数学服务只依赖 Python 3.12 与 sympy 1.13.3；不得注入任何平台密钥（阶段子进程以空环境运行）。

## 迁移 v68（edu_math_workbench_v68）
- AutoMigrate 16 张表：edu_org_policies、edu_role_bindings、edu_classes、edu_teaching_assignments、edu_enrollments、edu_problems、edu_problem_revisions、edu_math_jobs、edu_stage_runs、edu_artifacts、edu_solution_revisions、edu_lesson_revisions、edu_review_records、edu_publications、edu_assignments、edu_audit_events。
- 随后 applyFlowRLS：全部启用并 FORCE RLS，按 tenant_id 与 app.tenant_ids 隔离。
- 只新增表，不修改既有表。

## 迁移 v69（edu_classes_consent_v69）
- 新增 edu_class_invites、edu_consent_records（FORCE RLS）；edu_org_policies 增加 consent_mode 列（默认 guardian_required）。
- **上线影响**：默认要求监护人同意，已有学生在管理员记录同意或把策略设为 not_applicable 之前无法访问学习内容。这是有意的安全默认值。

## 迁移 v70（edu_student_learning_v70）
- edu_assignments 增加 starts_at、due_at、allow_late、answer_policy（默认 teacher_release）、answer_released_at、approx_allowed、unit_policy（默认 required）。既有任务因此默认不公开完整解答，直到教师公布。
- 新增 edu_attempts（tenant、学生、clientKey 唯一）、edu_hint_unlocks（任务、学生、层级唯一）、edu_self_tests、edu_review_items，全部 FORCE RLS。
- 旧二进制遇到 70 会拒绝启动（版本保护），因此代码回退到 v69 版本前需评估；表与列只新增，不删除。

## 迁移 v75（edu_job_price_book_v75）
- edu_math_jobs 新增 price_book（text），作业受理时写入当时价格簿。只新增，不删除。
- 旧作业 price_book 为空，结算回落到现行价格簿；如升级时有未结算的旧作业且价格簿已变，需人工对账（查询 settlement='open' 且 price_book 为空的作业）。
- 终态没有已计费阶段的作业 settlement 记为 released（原先统一为 settled）；报表按 settled 与 released 合并统计已关闭作业。
- CurrentSchemaVersion = 75。旧二进制遇到 75 会拒绝启动；回退前需评估。

## 迁移 v76（edu_ledger_anomalies_v76）
- 新增 edu_ledger_anomalies（tenant、job、kind 唯一），FORCE RLS。只新增，不删除。
- CurrentSchemaVersion = 76。旧二进制遇到 76 会拒绝启动；回退前需评估。
- 运维：建议每日由机构管理员或运维在应用内运行一次对账（POST /api/edu/ledger/reconcile）；自动定时对账尚未接入 worker。

## 回退
1. 功能回退：取消 FLOW_MATH_SERVICE_URL 并重启后端，/api/edu 与 worker 不再加载；数据保留。
2. 代码回退：回滚到更早版本的二进制。v68 的表保留不删除（无破坏性），重新升级时迁移幂等。
3. 不要手工删除 edu_* 表；涉及学生记录与账本，删除属于不可逆操作，需要书面批准。

## 恢复
- 作业状态以平台 edu_math_jobs 为准；worker 每 2 秒同步非终态或结算未完成的作业。
- 平台重启：worker 继续同步，按 seq 单调采纳，阶段结算按 (job, stage) 唯一，不会重复扣费。
- 数学服务重启：服务从数据目录恢复作业并按检查点续跑。
- 提交结果未知：作业为 reconciliation_required，预留保持；调用 POST /api/edu/jobs/:id/reconcile 或等 worker 自动对账。
- 数据目录丢失：已入库产物元数据仍在平台，但正文需要重新生成（接入对象存储后解决）。
