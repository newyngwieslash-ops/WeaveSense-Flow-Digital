# 旧 GIS 操作人信任链

本页为执行环境恢复后重新整理的说明，不冒充原本地文件的逐字恢复。
DT013 的实际结果以新的源码清单及测试证据为准，不能沿用旧候选的通过结论。

## 授权与兼容字段

平台会话和 DT012 签名验证是唯一可信用户身份来源。GIS 用服务器维护的显式绑定
把租户／工作区及稳定平台用户对应到旧项目／成员；不按名称、编码、默认成员或
浏览器存储自动认领。稳定用户 ID 不截断成旧编码。旧角色只是额外能力上限，
不能扩大平台签名动作或资源范围。

`operator_code`、`reviewer_code`、`uploader_code`、`requester_code`、`user_code`
和 `investigator_code` 不能选择另一执行者。作为业务指派目标的 `assignee_code`
必须与实际操作人区分。旧服务消费者凭据不是人类委托，尚未接入独立服务身份的
路径保持拒绝，不能凭旧 API key 获得项目管理员身份。

服务授权要求精确操作适配器：从实际方法参数查询对应对象及稳定资源映射，再与
完整签名范围核对。仅有同一项目、旧宽泛能力名或合法票据都不够。生产适配器注册表
默认空；缺少真实领域映射时保持不可用，不开放旧路由来模拟完成集成。

## 原子审计

旧服务包含内部 `commit()`。新审计通过受限 SQLAlchemy 会话与业务变更在同一
事务内提交，包含稳定主体、租户／工作区、旧成员当时角色、授权版本、动作和资源。
未知模型、缺少主体、未适配原生或批量写默认拒绝，不能把无 `project_id` 的对象
默认归属当前项目。提交／回滚清理主体，复用会话需要新的验证结果。

适配模型还要检查存储中的原始归属，不能通过修改字段重新归属来绕过范围。
任务范围的撤销历史可能同时涉及多个地块；A 地块票据不能改写同任务 B 地块历史。
实际 Workbench 集成负例保留上游语义，通过完整范围校验使越权请求整笔回滚。

旧身份、角色快照和历史审计保留原含义，不回填为未经证明的平台用户。
对象存储／消息／文件等外部副作用不因数据库审计而自动原子；后续任务仍须独立实现
持久任务、outbox 和业务幂等。

## 验证边界与恢复

原 `app.main` 不挂载旧业务路由，农业入口也不整体导入它们；前端身份选择及移动端
自动选角色不能提供生产授权。静态清单不是运行验收，未适配端点返回拒绝也不表示
业务已经可用。真实 PG fixture 验证成员绑定、权限、行锁、实际服务内部提交和审计
失败回滚；测试中的稳定地块映射明确只在测试进程安装，不是 W03 生产实体。

新表严格 RLS 不是 DT017 全 GIS 隔离完成。新原生本地 PG 测试不是 GitHub CI，
也不是现场试点。回退时关闭适配入口并保留绑定和审计，不恢复客户端身份信任。

详细入口清单见 `LEGACY_IDENTITY_INVENTORY.md`，绑定迁移见 `GIS_ACTOR_BINDINGS.md`，
旧服务门禁见 `W01_LEGACY_ACTOR_GATE.md`。所有新完成记录须绑定实际源码及证据。
