# 开发 Agent 续接与专项提示词

以下模板与AGENT_MASTER_PROMPT.md配合使用，不替代完整规格。SPEC_ROOT默认为specs/agriculture/v1.0.0。已授权范围内自主继续，只有具体外部权限/付费/生产副作用不明确时才请求必要授权。

## 1 日常续接或上下文恢复

继续开发WeaveSense-DigitalTwin。先读取工作区AGENTS、SPEC_ROOT/AGENT_MASTER_PROMPT.md、docs/implementation/STATUS.md、当前工作包记录、tasks.json与最近提交。核实未提交用户改动和依赖。保持PRD、架构及安全边界，选择最早依赖已满足且未完成任务，直接实施并验证。不要重新从零拟方案，不重复已经有证据且基线未变的工作。一个工作包完成后继续下一个就绪包，保存真实测试结果和下一检查点。

## 2 外部凭据或真实样本已经就绪

本次补充的环境/数据只用于原规格对应的真实验收。先识别哪些blocked_external任务因此解除，核对授权用途、预算、来源和秘密处理方式。禁止在日志或文档写入密钥。将fixture验收与live验收分开，执行最小必要真实闭环、保存时间/环境/回执/产物校验值，更新任务及门禁状态。对仍缺条件的任务继续保留阻塞，不把一次成功推广为全部来源已验证。

## 3 发布前独立审查

请以独立审查角色检查当前首版G0-G3。读取PRD、需求/任务JSON、源审计、架构、API契约、安全文档、验收矩阵及实际执行证据。重点验证跨租户地图/瓦片/对象/SSE/检索、空scope数据库角色、签名链接撤回、worker崩溃与旧租约、取消完成竞态、重复扣费/回调、影像scale/offset和云影mask、报告版本批准、tldraw及数据许可、备份恢复。只把有实际证据的项目列通过，输出阻断问题、复现步骤、受影响需求、最小修复和回归。修复已授权可逆问题后继续验证，不直接对外部署、收费或发送消息。

## 4 上游升级

评估新上游提交对当前产品的影响。先记录当前固定SHA、工作区和通过的基线证据，再读取目标提交差异。保留本地改动、版权许可和数据迁移历史。按模块评估API/模型/身份/RLS/Agent/依赖/构建变化，以最小范围升级并执行受影响回归；未验证前不能用新SHA替换旧审计结论。不强推、不自动覆盖目标分支，不以删除测试解决冲突。

## 5 进入S4或S5

在G3及相应依赖完成后，按W16/W17实施持续监测或预测决策。先确认真实设备/数据/模型权利和测量目标。缺少真实样本时可以建设契约及实验实现，但所有效果保持未验证。预测有适用域、输入快照、误差和模型版本；设备控制默认关闭，实际接入与激活另需明确范围授权和现场联锁验收。不要影响已经交付的S0-S3租户隔离和收费链路。
