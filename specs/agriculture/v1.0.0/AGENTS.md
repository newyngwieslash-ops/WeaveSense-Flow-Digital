# WeaveSense-DigitalTwin 开发约定

本文件是农业项目的补充开发规则。若代码仓库已有AGENTS.md，先读取并保留；将本约定按作用域合并或放在农业目录中，不能因解压规格而覆盖原规则。工作环境权限和用户当前指令始终优先。

## 交付范围

规格根目录SPEC_ROOT默认为specs/agriculture/v1.0.0，需求见PRD.md/requirements.json，任务见tasks.json。遵循DEVELOPMENT_PLAN.md、docs/ARCHITECTURE.md、docs/DATA_API_CONTRACTS.md、docs/SECURITY_TENANCY.md与验收矩阵。已授权实现范围内连续推进依赖就绪任务，不按每个工作包追加确认流程。

## 代码与来源

- WeaveSense-Flow为平台主干，AgriScope为农业GIS/遥感来源，保持固定提交和版权许可记录。
- 新开发在用户指定目标或独立目录/分支；不强推、不硬重置、不删除不相关改动、不向原上游推送。
- 先审查实际实现，避免按过期README重建已存在能力；上游更新记录diff及回归。
- 保持Go平台/农业GIS/Loom数据所有权，不跨服务直接写表。Python专业处理保留；前端采用已决定的渐进集成。
- 依赖有锁文件、SBOM和许可审查；农业production profile无未授权tldraw使用路径。不绕过许可或修改验证逻辑。

## 数据与安全

- 平台认证主体是唯一用户身份来源；所有GIS请求和worker任务明确tenant/workspace/resource作用域。
- 普通数据库连接无scope拒绝；系统任务用受控角色，数据库/服务内部端口不公开。
- 权限检查覆盖瓦片、对象、缓存、下载、SSE、导出、检索和工具。前端隐藏按钮不是授权控制。
- Geospatial数据保留CRS、单位、来源、精度和版本；真实数据、模拟数据和预测明确标识。
- 不记录秘密、授权header、完整签名URL；上传和外部URL按受控解析/SSRF策略处理。
- 设备控制默认禁用。试点和生产数据的外部发送、收费、发布与设备执行遵守具体授权，不以开发授权替代。

## 状态与正确性

- 长任务持久化，计算不依赖HTTP请求，不长持DB事务；租约/fencing防止旧执行者写回。
- 至少一次消息+幂等效果，不能依赖“消息只到一次”的假设。所有计费与对账路径可重放。
- 地块/作物季/输入/算法/报告版本可追溯，恢复是新增版本，不能改写历史证据。
- 质量不足明确insufficient_data；无数据不填随机值，模型不确定不生成确定农学结论。
- Agent不能执行任意生产SQL/shell；技能内容和检索文本不能提升权限。

## 测试与更新

每个任务的完成必须有代码/迁移/界面/异常路径及必要测试证据。使用真实PostgreSQL/PostGIS验证隔离和空间行为，不以SQLite替代这部分验收。CI fixture与live验证分别记录；未运行的测试写not_run，外部未就绪写blocked_external。

修复需覆盖真实失败路径，禁止删除失败断言、放宽权限、用静态mock或隐藏错误使检查通过。性能和恢复指标记录实际环境及测量结果。

更新SPEC_ROOT/docs/implementation/STATUS.md和任务状态；记录命令、退出码、产物路径与未解决项。每个工作包形成可审查提交或等价补丁，工作结束前记录下一任务。规格变更须在docs/DECISIONS.md说明理由、影响和验收调整，不静默删需求。

## 完成的含义

通过单元测试不代表完整验收，能启动不代表可商用。首版完成需满足G0-G3以及当前启用外部渠道的live证据。完整数字孪生增强需分别满足G4/G5，不得把规划功能标成已实现。
