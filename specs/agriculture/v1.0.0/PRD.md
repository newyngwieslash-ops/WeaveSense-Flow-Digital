# WeaveSense-DigitalTwin 项目 PRD

版本：1.0.0  
制定日期：2026-10-29，Asia/Shanghai  
产品性质：面向商业化的农业空间监测与数字孪生 Agent SaaS；应用闭源发行须满足各项独立许可  
技术主线：WeaveSense-Flow 平台 + 经改造的 AgriScope GIS/遥感服务  
文档状态：开发规格；所有实现与验收状态初始为未完成。用户已接受架构方向，本文件中的容量、套餐与阈值是本次工程默认值，须按真实试点验证。

## 1 产品目标与决策

让种植企业、合作社和农服团队围绕稳定的农场、地块和种植季，完成数据接入、地图标注、遥感变化分析、Agent解释、现场核查、报告交付及费用管理。首版交付可实际使用和收费的农业空间监测工作台；持续接入传感器、状态回放、经过验证的预测与作业反馈逐阶段形成数字孪生能力。

平台的核心价值是把“在哪里、何时发生什么变化、依据是什么、下一步如何核查、谁处理、结果怎样”连在同一个业务流程中。结果必须可以追溯到有权限访问的观测、输入版本、分析算子和人工处置。

**固定选型**：Go 平台拥有账号/租户/Agent/审批/预算账本与商业权益；独立农业 GIS 服务拥有农场、地块、影像、观测、分析、外业和领域审核；Loom 承担农业知识与外部证据采集。专业栅格处理保留 Python。React 为平台壳层，试点阶段复用 Vue GIS 子应用，后续按实际收益选择性迁移。[架构事实与许可证见来源审计](docs/SOURCE_AUDIT.md)。

### 2.2 首版边界

首版包括S0至S3的全部强制需求；移动交付为移动Web/PWA。GIS标注、实际影像分析、巡查、报告、Agent、计量和运营均需端到端运行。中文及中国农业单位优先，但区域、坐标、作物和报告字典可配置。

首版不包含完整无人机飞控、农机自动驾驶、自动施药、法定确权、保险法定定损、生产级作物机理模拟和未经验证的病害确诊。微信小程序和原生App属于后续渠道适配，不能因PWA存在而标为已交付。

S4增加设备与持续观测；S5增加经验证的预测和决策。设备控制始终为独立可选模块，默认关闭；实际生产激活须另有设备接入授权与现场验收。

## 3 目标用户与业务角色

| 角色 | 典型工作 | 关键权限边界 |
| --- | --- | --- |
| 租户所有者/管理员 | 邀请成员、套餐、预算、数据政策 | 管理组织不自动获得跨租户内容；不能篡改审计和账本 |
| 农场经理 | 农场档案、种植季、监测计划、巡查协调 | 仅管理获授权农场；高风险代理操作需明确审批 |
| GIS分析员 | 地块编辑、数据质检、分析与专题图 | 对指定农场资源操作；输入变更触发版本检查 |
| 巡查员 | 移动采集、复核疑点、记录实际作业 | 只访问指派范围及必要资料 |
| 审核员 | 复核成果、现场证据和报告 | 正式外发默认与作者分离；审核绑定具体版本 |
| 只读客户/外部接收人 | 查看获准地图、报告和交付物 | 显式资源范围、期限、撤销和下载控制 |
| 平台运维/客服 | 故障、计费、服务运维 | 默认无客户内容读取权，临时支持访问有工单及审计 |
| Agent/服务主体/设备 | 在给定范围执行工作 | 权限不能超过授权人和具体任务，不能自由选择租户 |

支持“一个机构多个农场”“一个农场多人协作”“农服机构被委托访问客户农场”。委托通过成员/资源授权表达，避免把客户数据复制到农服机构公共空间来绕过权限。

## 4 用户价值与衡量方式

以下是待试点验证的产品目标，不是已获得的业务成绩。

| 目标 | 衡量方法 | 首次验收要求 |
| --- | --- | --- |
| 可完成真实监测闭环 | 从授权地块/影像到异常、巡查和报告 | 至少2个真实授权农场、1类主要作物、2期可用影像，跑通至少1次完整闭环；不足则明确延期该项 |
| 降低手工整理成本 | 与客户原有流程记录同任务用时 | 记录基线、平台用时、人工修正和支持工时，形成试点报告，不预设“节省百分比”结论 |
| 提升证据可追溯性 | 报告数字抽样回查输入与算法 | 发布报告的核心数字全部有可定位来源；随机抽样复算一致 |
| 控制误报 | 异常与现场核查关联 | 记录确认、误报、无法验证与原因；按作物/地区/季节评估，不混成单一漂亮准确率 |
| 具备收费基础 | 套餐、计量、支付/账务对账 | 启用的收费渠道必须完成真实验收；未验收渠道不能开放给客户 |
| 支持重复使用 | 两次监测周期和用户反馈 | 获得实际复用记录与问题清单；商业继续投入以客户反馈和成本为依据 |

## 6 核心业务流程

### 6.1 农场初始化

管理员创建组织和农场，配置区域/时区/面积单位，导入有授权的地块，预览CRS、几何、字段和重复项，确认后写入地块及版本。新建种植季，补充作物与基本农事资料。没有正式数据时保持空状态，演示沙箱可单独进入。

### 6.2 影像接入与分析

用户选择农场、种植季、时间范围和分析目的。系统检索获准数据源或接收上传，校验实际文件与元数据、像元质量、覆盖和费用。用户确认分析参数后创建持久作业。结果可用前完成输出校验和质量门禁；结果展示地图图层、统计、依据、适用范围与成本。云遮挡等原因导致不足时，返回insufficient_data及补数建议。

### 6.3 自然语言监测

示例请求：“比较一号农场本种植季最近两期可用影像，找出玉米地变化较大的区域，显示在地图上并生成巡查草稿。”Agent读取授权上下文并选择工具；实际数值来自工具。长任务返回任务卡，完成后更新地图。草稿包含待核查假设，实际指派前按审批策略展示对象、变更和费用。

### 6.4 巡查与反馈

负责人审核草稿、指派巡查员。移动端下载必要任务资料，现场采集定位、精度、照片和结论，弱网先保存草稿并补传。审核员确认异常、误报或需继续观察。后续作业记录与观测形成时间线，系统不自动将“处理后变化”描述为已证明因果。

### 6.5 正式报告与共享

报告绑定地块版本、影像/分析/巡查快照、来源许可、图层样式及模板版本。正式外发默认需要独立审核，审核后的修改形成新revision并使原批准失效。接收人通过限时授权访问，撤回后停止新访问；普通预签名链接的残余有效期必须透明，敏感交付使用可撤销网关。

### 6.6 费用和失败处理

任务提交时冻结费率和预算上限；仅在确证未接单、未执行且不会再执行，或已确定应释放金额时释放相应预留。网络超时、回执丢失或远端状态未知进入reconciliation并保持必要预留，先查询或取消确认，不能把未知当作未执行。执行成功按计量结算，取消后按已披露规则处理实际消耗；抑制重复提交，不得同时退款又再次扣费。套餐到期限制新收费任务，保留合同约定的只读/导出窗口。

### 8.1 容量测试假设

参考测试环境暂定8 vCPU、32GB RAM、SSD、同区域对象存储，试点档20并发会话、每租户10万地块目录；地图必须视窗过滤/分页或MVT，不能一次返回全部几何。5000万像元影像处理属于需验证的分块扩展场景，远大于上游部分默认上限，实施时先做资源评估。影像算法时长单独报告，不把“任务提交1秒”宣传成“影像1秒算完”。

这些数值用于统一测量协议，不构成已实现能力或客户SLA；最终容量以测量结果、业务范围和成本预算决策。省域超大规模、多租户高并发和万台设备不在首版容量承诺中。

## 9 领域数据与生命周期

关键实体为Tenant、Workspace、Farm、Parcel、ParcelRevision、ParcelLineage、CropSeason、CropAssignment、DataAsset、AssetRevision、RightsRecord、Observation、AnalysisJob、AnalysisRun、ArtifactManifest、Anomaly、InspectionOrder、FieldEvidence、FarmOperation、ReportRevision、ReviewRecord、Publication、AgentProfile、CapabilitySnapshot、UsageRecord与BillingReservation。

空间事实权威存于flow_geo；账号和商业权益权威存于flow_platform；知识材料权威存于flow_intel。跨库只通过API和版本化事件交互。主键统一使用不承载业务秘密的稳定ID；唯一约束和外键必须包含适当租户范围，防止通过关联写入跨租户对象。

观测至少区分observed_at、ingested_at和source_updated_at；预测另存forecast_issued_at和target_time。时间一律UTC存储，显示业务时区。地块边界变化不改写旧观测，报告引用明确revision；同一对象的历史、当前和预测状态各自可识别。

原始/派生文件不可原位覆盖；数据库保存版本、hash与引用。删除采用受控生命周期：请求、冻结新处理、检查依赖、清理索引/缓存/对象、最小审计保留。业务撤回与物理删除是两种不同操作。

## 10 Agent产品要求

首版预置GIS助手、长势巡检助手、巡查协调助手和报告助手。一个用户可以切换业务助手，也可在权限范围内创建租户Agent配置。自定义提示词不会产生额外权限；上下文和工具集在每次运行时由平台重解析并冻结版本。

Agent输出必须能回到具体农场/地块/种植季/图层。建议的结果载体包括：资源卡、job状态卡、地图动作、表格、报告草稿、审批预览。地图动作只能引用已授权的layer_id/artifact_id，不能让LLM注入任意远程图层URL或JavaScript。

工具按只读、收费计算、业务写入、外部分发和设备控制分级。确定性读工具可在授权范围直接执行；已授权的计算在预算内运行；改变地块、正式指派和发布按策略审批；设备控制默认不开放。审批与代码开发权限不同，开发Agent实施已授权规格不需要每个工作包重复征求确认。

知识检索返回原始来源及可访问引用；文档内的指令是非可信内容，不能更改系统权限。禁止通过任意SQL、shell或可执行Skill直接访问生产数据库、对象存储和设备。

## 11 商业模式与运营要求

建议采用团队/农场基础订阅加监测与分析额度，超额按明确计量收费。计费维度可包括席位、管理地块/面积、存储、分析处理量、模型调用和设备量。首版价格只配置测试价与可审查价格表，不自行替用户决定最终人民币套餐或对外承诺毛利。

支付采用provider接口，选定渠道后实现并验收。商户资料和生产密钥不足时，开发可先完成沙箱、验签、幂等、对账和退款逻辑；真实收费渠道保持关闭并标blocked_external。若经用户选择采用人工合同/对公结算，需记录订单和账务凭证，并单独明确其权益开通及对账流程，不冒充自动支付已验收。

运营后台展示租户服务状态、用量、异常账单、任务故障和授权工单。客户支持不以后台万能账号直接浏览所有农场资料；必要的支持访问限定对象、时间及原因并记录审计。

## 12 错误与退化行为

| 场景 | 用户可观察行为 |
| --- | --- |
| 无真实影像/设备/模型 | 显示空状态与缺失依赖，不填充随机正常数据 |
| 影像覆盖或有效像元不足 | 显示insufficient_data、原因、有效范围和补数建议，报告不能形成确定农学结论 |
| 权限撤销 | 新请求立即按策略拒绝；长任务、SSE、共享和缓存按撤销规则处理 |
| 数据源或模型服务中断 | 作业标记可重试/等待，不无限重试付费调用；展示更新时间 |
| 并发修改地块 | 返回版本冲突并保留当前草稿，不静默最后写入覆盖 |
| 成果来源被撤回 | 标记历史/失效，阻止新正式发布，给出依赖和处理动作 |
| worker中断 | 租约过期后可重驱；旧worker不能发布；不重复结算 |
| 预算不足/额度用完 | 提交前告知费用与额度，不进入无上限计算 |
| 取消与完成竞争 | 唯一终态，有可解释费用，禁止既显示取消又发布当前成果 |
| 移动弱网 | 草稿和待上传照片可见；幂等补传后明确同步成功 |

## 13 真实数据与验证设计

CI使用小型、合法、确定性fixture验证算法和状态机；至少一个真实STAC数据源、真实模型服务、生产对象存储及选定收费方式要有独立live证据。现场验证必须记录地块授权、日期、作物/物候、采集设备、定位精度、人员、照片和结论。

公开10米级遥感影像不能被默认描述为单株病害识别数据。小地块与边缘混合像元在质量门禁中单独标注；影像分辨率、面积、采样尺度和误差表达需一致。农学模型效果按地区/品种/季节分层，训练集与验证集避免时间和空间泄漏。

验收分成G0至G5，与S0至S5对应；详细前置、步骤、期望、反例、证据和状态在[验收矩阵](docs/ACCEPTANCE_MATRIX.md)。演示截图或“测试文件存在”不能替代执行结果。

## 15 完成定义

首版“完成”必须同时满足：S0-S3需求有实现、迁移和界面；授权链路端到端生效；真实影像与计算产物可追溯；费用幂等且可对账；Agent能够调用真实工具并受审批限制；真实客户闭环、备份恢复、支持与部署手册齐备；当前发布启用的外部渠道有相应live证据；全部阻断项公开记录。

代码已写、fixture已过、live待验收、试点可用和商用可发布是不同状态，任何报告不得混用。S4/S5后续工作保留完整任务与验收条件，不能为宣称“完整数字孪生”而把未验证的预测或模拟页面标已完成。
